# ИИ-Мастер — текстовая RPG по D&D 2024 с ИИ-ведущим

Веб-игра: текстовая ролевая игра по правилам D&D 2024 (SRD 5.2). Роль ведущего (Мастера)
исполняет языковая модель через API поставщика, выбранного в настройках (например, DeepSeek).

## Стек

- Vite + React + TypeScript.
- **Без бэкенда.** Весь код работает в браузере игрока.
- Сайт статический, публикуется на GitHub Pages (`https://<user>.github.io/dnd_ai_master/`).

## Архитектура: код — правила, ИИ — рассказ

Главный принцип: **код — единственный источник истины о состоянии игры.**

- **Код отвечает за:**
  - правила SRD 5.2 (проверки, спасброски, атаки, урон, отдых, условия и т. д.);
  - броски кубиков (только в коде, с честным ГСЧ; ИИ не «придумывает» результаты) —
    модуль `src/engine/dice.ts`: запись `1d20+5`, `4d6kh3`, преимущество/помеха, подробный результат.
    Все случайные числа игры — только через него; в тестах генератор подменяется (`rng`);
  - правила проверок — `src/engine/`: `abilities.ts` (характеристики, модификаторы, бонус мастерства),
    `skills.ts` (18 навыков, владение и компетентность), `conditions.ts` (15 состояний и их влияние на
    броски к20), `checks.ts` (`abilityCheck`, `savingThrow`, `passivePerception`, `formatD20Test`).
    Проверка возвращает подробный результат: режим и его причины, разбивку модификатора, бросок, успех.
    В SRD 5.2 натуральные 20/1 не дают автоуспеха/автопровала проверкам и спасброскам — только атакам;
  - состояние игры: персонаж, характеристики, хиты, инвентарь, текущая локация, флаги сюжета.
- **ИИ-ведущий отвечает за:**
  - повествование и описание сцен, реплики НПС;
  - решение, *когда* нужна проверка (какой навык/характеристика, какая Сл) — в виде
    структурированного запроса, который код валидирует и исполняет.
- **ИИ никогда не меняет состояние напрямую.** Он может только *предлагать* действия
  (например, через tool use / структурированный JSON-ответ: «запроси проверку Ловкости (Скрытность) Сл 15»,
  «предложи передать предмет X»). Код проверяет запрос по правилам и текущему состоянию,
  применяет его сам и сообщает ИИ результат для дальнейшего рассказа.
- **Игра состоит из независимых историй (кампаний).** Все игровые данные **всегда принадлежат конкретной истории**:
  отряд героев (`party` — список, код не должен рассчитывать, что герой один), мир (`world`: собственные копии локаций,
  двери, НПС, факты, квесты), журнал приключения, лог сообщений и бросков. Тип — `StoryState` (`src/types/story.ts`).
  Истории не смешиваются: ничто из одной истории не читается и не меняется из другой.
- **Состояние истории меняется только через действия** (`StoryAction`): тип, автор (`player` с героем, `engine`, `master`,
  `system`) и время — «игрок сказал», «движок бросил кубик», «ведущий переместил НПС». Состояние — применение действий
  по порядку (`applyAction`/`replay` в `src/game/storyActions.ts`); применение детерминировано, всё случайное (id, броски,
  время) записано в самом действии. Перед записью действие проверяется по правилам (`checkAction`). Журнал действий
  хранится целиком — задел под мультиплеер (действия можно будет передавать между игроками).
  Новое изменение состояния = новый тип события в `StoryEvent` + ветка в `applyEvent` + проверка в `checkAction` + тест.
- **Хранение — IndexedDB через Dexie** (`src/game/repository.ts`, база `ai-master`): `stories` (сведения для списка),
  `actions` (журнал, ключ `[storyId+seq]`), `snapshots` (кэш последнего состояния; если он отстал — журнал воспроизводится),
  `heroes`, `hall`. localStorage только для мелочей интерфейса (выбранная вкладка), настроек оформления устройства
  (`ai-master:appearance`, свои темы — `ai-master:custom-themes`), настроек ведущего (`ai-master:ai`, ключ —
  `ai-master:api-key`, поправки подсчёта токенов по моделям — `ai-master:token-calibration`) и отладочного флага.
  Хранилище приложения — `src/game/appStore.ts` (экземпляр `src/game/appInstance.ts`, в React — `useAppState()`):
  открытая история, команды (`createStory`, `dispatch`, `dispatchTo`, `renameStory`, `deleteStory`, `completeActive`,
  герои), запись в базу строго по очереди (`flush` — дождаться записи).
  Старое сохранение из localStorage (`ai-master:save` v1–8 и `ai-master:heroes`) переносится при запуске
  (`src/game/legacyImport.ts`, миграции старого формата — `legacySave.ts`/`legacyState.ts`), копия — `ai-master:legacy-backup`.
  При несовместимом изменении `StoryState` — менять формат так, чтобы старые журналы воспроизводились (или переносить их).
- Экраны: «Мои истории» (`StoriesScreen`: продолжить, новая, переименовать, удалить с подтверждением), «Новая история»
  (`NewStoryScreen`: свободный герой или новый, название, тон — тёмное фэнтези / лёгкое приключение / детектив / хоррор,
  приключение). Название и тон попадут в системный промт ведущего. Приключения — `src/data/adventures/`
  (локации, стартовая локация, вступление, тон по умолчанию); таверна «Пьяный грифон» — по умолчанию.
- Логику правил держать чистыми функциями, отдельно от React-компонентов и от слоя работы с API,
  чтобы её было легко тестировать.
- **ИИ-ведущий работает через общий интерфейс `src/ai/`, поставщик модели выбирается в настройках, а не в коде.**
  `src/ai/types.ts` — интерфейс `AiMaster.complete(запрос)`: сообщения (`system`/`user`/`assistant` с вызовами
  инструментов/`tool`), описания инструментов, `toolChoice`, стриминг (`onText`) → текст, вызовы инструментов
  (несколько в одном ответе), расход токенов. Игра знает только этот интерфейс и `createMaster(подключение)`
  (`src/ai/index.ts`); формат API — дело адаптера в `src/ai/adapters/` (сейчас один — OpenAI Chat Completions,
  `openaiChat.ts`: tools, tool_choice, `stream: true`, SSE). Адаптер терпим к вариантам OpenAI-совместимых сервисов
  (DeepSeek, Polza, OpenRouter): комментарии и keep-alive SSE, куски без choices / с пустым delta, конец без [DONE],
  обычный JSON вместо потока, поток с неверным типом содержимого, `event: error`, «размышления» рассуждающих моделей
  (`reasoning`/`reasoning_content` → `AiResponse.reasoning`, игроку не показываются), вызовы инструментов по частям;
  если сервис не знает `stream_options` — повтор без него. Каждый новый вариант формата — модульный тест
  в `openaiChat.formats.test.ts`. Ошибки указывают, на чём споткнулись (`AiError.stage`); «Диагностика» в настройках
  (`AiMaster.diagnose`) показывает статус, заголовки и первые 20 строк сырого ответа без ключа и Authorization. Новый формат = новый адаптер + строка в реестре
  `ADAPTERS` и в `AI_FORMATS`; код игры не меняется. Ошибки — `AiError` с видом (`auth`, `billing`, `rate-limit`,
  `network`, `model-not-found`…) и понятным текстом; лимит запросов и перегрузка повторяются автоматически с паузой
  (если текст уже пошёл потоком — без повтора). Проверка подключения — `src/ai/check.ts` (ключ, стриминг, несколько
  вызовов инструментов). Настройки — `src/ai/settings.ts` (пресет «DeepSeek»: https://api.deepseek.com, `deepseek-chat`;
  «Свой» — адрес, модель, формат вручную; длина ответов коротко/обычно/подробно), хранилище — `settingsStore.ts`.
  **Системный промт ведущего — `src/ai/dm-prompt.md`** (роль, стиль, свобода, честность бросков, решения игрока — только
  его, конец ответа — ситуация для реакции, что знает герой и что — только ведущий, игрок заявляет намерение, а не
  результат); правки поведения ведущего — в этом файле (тест `masterTurn.test.ts` проверяет ключевые правила).
  Ручная проверка ведущего на живой модели — сценарии в `docs/dm-test-scenarios.md` (после смены модели или
  правки промта пройти заново; новое найденное слабое место — новый сценарий и правило в промте). К нему в каждом запросе добавляются эта история, длина ответа и **актуальное состояние игры**
  (`src/game/masterState.ts`: лист персонажа, языки, приёмы оружия и воззвания, «История героя» и «Летопись», инвентарь и экипировка, текущая локация с помещениями, объектами,
  дверями в их текущем состоянии и НПС с положением, задания, факты) — собирается заново для каждого запроса.
  Запрос ведущему по истории — `src/game/masterPrompt.ts` (`buildMasterRequest`), ход — `src/game/masterTurn.ts`;
  ответ записывается действием `masterNarrated`.
  **Память ведущего** (сжатие контекста делаем сами, независимо от поставщика):
  - Запрос собирается из частей в **постоянном порядке**, неизменная часть первой (кэш префикса у поставщика):
    правила (dm-prompt.md, история, длина ответа) → инструменты (поле `tools`) → «Что было раньше» (сводка
    `StoryState.memory`) → журнал фактов (`world.facts`, всегда целиком, не сжимается) → состояние игры → последние
    сообщения (лента после `memory.covered`) → действие игрока. Порядок частей — `PROMPT_PARTS`.
  - Бюджет: окно контекста модели (у пресета — `AI_PRESETS.*.contextWindow`, у «Своего» — в настройках) и целевой
    размер запроса (`targetTokens`, по умолчанию 20 000) — `contextBudget`. Токены считаются примерно
    (`src/ai/tokens.ts`: символы с поправкой на кириллицу), коэффициент уточняется по usage ответа
    (`calibrationStore`, по моделям). Если запрос рискует не влезть в окно (`hardLimitOf`: окно − ответ − запас), из него
    убираются самые старые сообщения, затем начало сводки, затем самые старые факты (в истории всё остаётся).
  - Сжатие — `src/game/memory.ts`, инструкция модели — **`src/ai/compact-prompt.md`** (что сохранить/выбросить, стиль
    заметок, задачи: сжать фрагмент, пересжать сводку, объединить факты, итог истории). Запускается **в фоне после
    ответа**, если следующий запрос больше бюджета (`compactionNeeded`): старая лента (кроме последних `KEEP_RECENT` = 10)
    по фрагментам — сначала модель записывает недостающее `note_fact`, потом строки сводки → действие `memoryCompacted`
    (лента не меняется). Сводка длиннее `SUMMARY_SOFT_CHARS` — пересжимается (давнее короче); журнал фактов разросся
    (`factsTooLarge`) — объединяется действием `factsMerged` (движок не примет, если потеряно имя — `lostNames`).
    Модель сжатия — отдельная в настройках (`compactModel`, по умолчанию та же). Ошибка сжатия не ломает ход
    (пишется в журнал разработчика). Ошибка API «слишком длинный контекст» (`AiError` вида `context-length`) —
    принудительное сжатие (`KEEP_RECENT_FORCED`) и один повтор хода.
  - Факты — заметки мастера: одна строка до ~20 слов (правило в compact-prompt.md, dm-prompt.md и описании
    `note_fact`); движок (`src/game/facts.ts`) отклоняет длинные с просьбой сократить, похожий на записанный факт
    обновляет старую запись (`factUpdated`).
  - Игроку — вкладка «Журнал» в листе персонажа (`AdventureJournal`: сводка и факты). Разработчику — «Настройки» →
    «Ведущий» → «Журнал разработчика» (`src/game/devLog.ts`, только в памяти вкладки): размер каждой части запроса,
    сколько токенов пришло из кэша (`AiUsage.cachedInputTokens`), когда и сколько сжато.
  - Кэш: DeepSeek и OpenAI кэшируют префикс сами; если поставщику нужно включать кэш вручную — это делает адаптер,
    не код игры.
  **ИИ меняет игру только инструментами** (`src/game/masterTools.ts`, `MASTER_TOOLS`): `request_check` (движок
  бросает проверку/спасбросок с учётом состояний — действие `checkRolled`, в ленте карточкой `CheckCardView`),
  `give_item`/`remove_item` (отдал, потерял, сломал), `use_item` (израсходовал: стрела, рацион, факел, зелье, заряд набора
  целителя — движок списывает штуки или заряды и применяет эффект из справочника, зелье лечения — бросок лечения
  движком), `change_gold` (монеты: amount + currency `cp`/`sp`/`gp` или `price` из прейскуранта; сдачу считает движок;
  денег не хватает — отказ), `change_hp` (урон с типом/лечение; 0 хитов — Без сознания, массивный урон — гибель от движка), `move_npc`/`add_npc`/`remove_npc`, `add_condition`/`remove_condition`, `note_fact`,
  `cast_spell` (заклинание из листа героя: движок проверяет, что оно известно или подготовлено, и тратит ячейку —
  заговор, ритуал и бесплатное сотворение без ячейки; сам бросает атаку, спасбросок цели-героя, урон, лечение — событие
  `spellCast`), `rest`/`interrupt_rest` (отдых — см. «Отдых»), `use_feature` (умение класса с применениями, лечение
  «Второго дыхания» бросает движок — `featureUsed`), `add_object`/`remove_object`/`update_object` (координаты, пол, стены, свободные клетки — `src/game/mapPlacement.ts`;
  на стул НПС сесть может), `set_door`. `executeTool` проверяет аргументы и состояние, превращает вызов в действия
  и прогоняет их через `checkAction` на копии истории; недопустимый вызов отклоняется с причиной (модель получает
  `{ ok: false, error }`), история не меняется. Цикл хода (`runMasterTurn`): ответ модели → текст перед вызовами
  в ленту → инструменты по одному → результаты модели → … → финальный текст; не больше `MAX_TOOL_ROUNDS` раундов,
  в последнем `tool_choice: none`. **Ничего не меняется словами:** каждый ответ ведущий заканчивает служебным
  `end_turn` со списком изменений листа за ход (деньги, предметы, хиты, состояния) или пустым — `src/game/turnChanges.ts`
  сравнивает его с тем, что реально изменилось (снимок героев до и после хода, `ledgerOf`/`turnDelta`/`verifyEndTurn`);
  если чего-то не хватает или end_turn нет — **один** повтор с просьбой довызвать инструменты (`END_TURN_REMINDER`;
  после напоминания новый текст не дописывается, после расхождения — дописывается, чтобы обыграть отказ). Итог сверки —
  `MasterTurnResult.verification`, в журнале разработчика вместе с каждым вызовом инструмента. После ответа — строка
  изменений («−4 мм (эль)», «−1 стрела», «+5 хитов») действием `turnSummarized` (системное сообщение с `changes`,
  `lastNarrative` его пропускает для подсказок и «Переписать ответ»); в листе изменившееся значение подсвечивается
  (`Flash`). Сценарии проверки — 11–16 в `docs/dm-test-scenarios.md`. Текст ведущего идёт в ленту потоком; пока ведущий отвечает, поле ввода заблокировано
  и видна анимация «Мастер думает…». **Подсказки действий**: ведущий заканчивает ответ строкой
  «Варианты: … | … | …» (правило — в `dm-prompt.md`); `src/game/masterSuggestions.ts` вырезает её из рассказа и из потока
  (`splitSuggestions`, `streamingText`), подсказки (до 3) хранятся в `masterNarrated.suggestions` и показываются кнопками
  под полем ввода у последнего ответа — нажатие вставляет текст в поле, не отправляя. **«Переписать ответ»** — только
  у последнего сообщения ленты, если это ответ ведущего (`rewritableMessageId`): `runMasterRewrite` просит модель
  написать его заново **без инструментов** (игра не меняется, перебросить кубики нельзя), результат — действие
  `masterRewritten` (новый текст на месте старого; старый остаётся в журнале действий). Новый инструмент = описание в `MASTER_TOOLS` + обработчик + (если нужно) событие
  истории + тест на недопустимые вызовы в `masterTools.test.ts`. Без настроенного ведущего игра отвечает заглушкой.
  **Сроки и отмена запросов к ИИ**: `src/ai/timeouts.ts` (`AI_TIMEOUTS` — общий срок и срок простоя без кусков потока,
  отдельно для хода ведущего; в e2e — `window.__aiMasterTimeouts`), `src/ai/timed.ts` (`timedMaster`: обрывает запрос
  по сроку или отмене, ошибка `AiError` вида `timeout` с понятным текстом; `AiRequest.onProgress` — куски ответа от
  адаптера). `timedFor` в `src/game/masterSession.ts` пишет каждую попытку в журнал разработчика (длительность, размер
  запроса и ответа, первый кусок, «размышления» модели). Рассуждающая модель (`isReasoningModel`) — предупреждение
  в настройках и при подборе. Вне ленты — один общий индикатор: `useAiTask` (`src/components/useAiTask.ts`) +
  `AiProgress`/`AiTaskError` (`src/components/AiTask.tsx`: этап, секунды, получено символов, «Отменить»; ошибка или
  тайм-аут — сообщение и действия) — подбор предыстории, проверка подключения и «Диагностика», итог истории для
  летописи (окно поверх игры; «Отменить» — черновик из журнала). В ленте у «Мастер думает…» — «Отменить» и тайм-аут
  («Повторить»).
  CORS: DeepSeek принимает запросы прямо из браузера (проверено), прокси не нужен; если поставщик «Свой» не разрешает
  запросы из браузера, адрес прокси указывается вместо base URL. Тесты адаптера — с подменёнными ответами
  (`src/ai/testing.ts`), e2e — `page.route` (настоящих запросов к API в тестах нет).

## Данные игры — в JSON

- Все игровые данные (локации, предметы, НПС, а позже — монстры, заклинания и т. п.)
  хранятся в JSON-файлах (`src/data/`), а не захардкожены в коде.
- **Источник правил — `docs/srd/SRD_CC_v5.2.1.pdf`** (SRD 5.2.1). Данные сверяются с ним, а не с памятью: текст —
  `pdftotext` по колонкам (`-x/-W` половины страницы), таблицы — `pdftotext -layout`. Итог сверки и что не сделано —
  `docs/srd/reconciliation.md`. Русские названия — наш перевод, английское из SRD хранится рядом: `nameEn` у заклинаний,

## Ключ API

- Бэкенда нет, поэтому ключ API поставщика модели вводит сам игрок в «Настройки» → «Ведущий» (поле скрыто).
- Ключ хранится **только в браузере игрока** (localStorage `ai-master:api-key`, отдельно от остальных настроек)
  и отправляется только по адресу API из настроек (только https; http — лишь для localhost).
- Ключ не попадает в сообщения об ошибках: тексты ошибок свои, подробности поставщика проходят `redactSecrets`.
- Никогда не коммитить ключи, не вшивать их в сборку, не отправлять на сторонние сервисы и не логировать.

## Интерфейс

- Весь интерфейс и все тексты для игрока — **на русском языке**.
- ИИ-ведущий тоже ведёт игру на русском.

## Оформление — только дизайн-токены

- Всё оформление задаётся **одним объектом темы** в `src/theme/`: цвета интерфейса (`colors` → `--color-*`),
  цвета карты — пол, стены, окна, двери, объекты, рамки фишек (`map` → `--map-*`), кубики и подсветка натуральных 20 и 1
  (`dice` → `--dice-*`), шрифты (`--font-*`), размеры текста (`--text-*`), отступы (`--space-*`), скругления
  (`--radius-*`), тени (`--shadow-*`). Формат — тип `Theme` и списки ключей (`src/theme/types.ts`), схема zod
  (`src/theme/schema.ts`, `parseTheme`). Текущая тема — «Тёмное фэнтези» (`src/theme/darkFantasy.ts`).
- Тема по умолчанию встраивается в `index.html` как `<style id="theme">` с CSS-переменными (плагин в `vite.config.ts`,
  `themeCss`). Темы проверяются схемой при сборке; zod в сборку для браузера не попадает.
- **Несколько тем — реестр** `src/theme/registry.ts` (`themes`, `themeById`, `DEFAULT_THEME_ID` = `dark-fantasy`).
  Темы дизайнера — JSON-файлы `design/themes/<id>.json` (см. `design/themes/README.md`): плагин Vite читает папку,
  проверяет каждый файл `parseTheme` (`loadDesignThemes` в `src/theme/designThemes.ts`: JSON, схема, имя файла = id,
  id не повторяются) и отдаёт реестру через виртуальный модуль `virtual:design-themes`. Некорректный файл ломает сборку
  с ошибкой «файл: поле: что не так». Темы дизайнера не придумывать — их присылает дизайнер.
- **Экран настроек** (шестерёнка в шапке на всех экранах; `src/components/SettingsPanel.tsx`; десктоп — боковая панель,
  телефон — шторка): вкладки «Оформление» и «Ведущий» (`MasterSettings.tsx`). **Оформление**: карточки всех тем реестра с мини-превью, акцентный цвет (`ACCENTS`; показываются только читаемые
  с `onAccent` темы), шрифт текста ведущего (`MASTER_FONTS` — 4 шрифта с кириллицей из @fontsource, токен `fonts.master`),
  размер текста (4 шага — масштаб корневого шрифта), плотность (компактная — отступы темы × 0.7), сетка карты и её
  прозрачность, подписи НПС, анимации (по умолчанию — как системное «уменьшить движение»), сброс.
  Это **настройка устройства, а не истории**: `AppearanceSettings` (`src/theme/appearance.ts`) в localStorage
  `ai-master:appearance`. Применяет их `bootAppearance` (`src/theme/boot.ts`) — **самодостаточная функция**: плагин
  встраивает её текст в `<head>` (`<script id="appearance-boot">`), поэтому оформление применяется до первой отрисовки,
  без вспышки; та же функция применяет изменения из панели (`appearanceStore`/`useAppearance` в `appearanceStore.ts`).
  В ней нельзя ссылаться на импорты и внешние переменные (это проверяет тест). Результат — переменные на `<html>` и
  атрибуты `data-theme`, `data-density`, `data-map-grid`, `data-npc-labels`, `data-motion` (стили анимаций — через
  `:root[data-motion='reduce']`, а не через `@media (prefers-reduced-motion)`); прозрачность сетки — `--pref-grid-opacity`.
- **Свои темы игрока** (`src/theme/customThemes.ts`, UI — `src/components/CustomThemes.tsx`): «Сохранить как свою тему»
  из текущего оформления (акцент, шрифт ведущего и плотность запекаются в токены, `themeFromSettings`), несколько тем
  (до 20, id `custom-…`), переименование, удаление; редактор основных цветов (`EDITABLE_COLORS`: фон, текст, акцент,
  панели, карта; `withColor`) — изменения сразу применяются ко всей странице; предупреждение, если пары контраста ниже
  WCAG AA (`readabilityWarnings`). Экспорт — JSON в формате тем дизайнера; импорт проверяется `parseTheme` (zod грузится
  отдельным чанком только при импорте) и получает новый id. Хранение — localStorage `ai-master:custom-themes`
  (`CustomThemeRecord`: исходная тема + готовые переменные `compiled`, чтобы `bootAppearance` применил свою тему
  до первой отрисовки). Своя тема — настройка устройства, к историям не относится.
- Параметр адреса `?theme=<id>` временно включает тему из реестра поверх сохранённой (до выбора темы в панели),
  ничего не сохраняет. В e2e тему можно добавить на время страницы: `window.__aiMasterAppearance.addDebugTheme(тема)`.
- Контраст по WCAG — `src/theme/contrast.ts` (`CONTRAST_PAIRS` — пары «текст на фоне», `themeContrast`): для каждой темы
  реестра каждая пара ≥ 4.5:1 (AA), у темы `high-contrast` — 7:1; полупрозрачные цвета — по итоговому цвету на фоне.
  Тест `contrast.test.ts`; пары, которые пока ниже порога и ждут решения владельца, перечислены в нём (`KNOWN_ISSUES`) —
  цвета тем без согласия владельца не менять. e2e `e2e/themes.spec.ts` для каждой темы открывает главный экран и создание
  персонажа на телефоне, проверяет отсутствие горизонтальной прокрутки и прикладывает скриншоты к отчёту.
- **Новые элементы интерфейса используют только токены**: в CSS — `var(--color-…)`, `var(--space-…)` и т. д.,
  в коде (SVG, inline-стили) — `token('map', 'fireGlow')` из `src/theme/css.ts`. Цвета напрямую (`#hex`, `rgb()`,
  `hsl()`, именованные) вне `src/theme/` запрещены — их ловит тест `src/theme/noRawColors.test.ts`.
  Нужен новый цвет, размер или тень — добавить ключ в `types.ts` и значение в тему (тест `theme.test.ts` проверяет,
  что каждая переменная в стилях задана темой и в теме нет неиспользуемых токенов).
- Шкалы `--text-*` и `--space-*` — ступени (в базовой теме ключ = сотые доли rem / пиксели); новых ступеней без нужды
  не заводить, брать ближайшую существующую. Переменные-параметры компонента (`--board-w`/`--board-h` карты) — не токены.

## Сборка и публикация

- `npm run dev` — локальная разработка.
- `npm run build` — проверка типов и сборка в `dist/`.
- `npm run lint` — линтер (oxlint).
- `npm test` — тесты (Vitest), `npm run test:watch` — в режиме наблюдения. Тесты лежат рядом с кодом: `*.test.ts`.
  Логику правил и валидаторы данных покрывать тестами.
- `npm run test:e2e` — e2e-тесты Playwright (`e2e/*.spec.ts`) на собранном сайте: сначала `npm run build`.
  Два проекта: `desktop` (1440×900) и `mobile` (iPhone 13 на Chromium). Сайт отдаёт `e2e/serve.mjs`
  по пути `/dnd_ai_master/`, как GitHub Pages. Случайность в e2e подменяется через `installRngQueue`/`queueRolls`.
  Новые элементы интерфейса покрывать e2e-тестами, на телефоне проверять отсутствие горизонтальной прокрутки.
  Импортировать `test`/`expect` из `e2e/fixtures.ts`: на телефоне он подставляет широкий шрифт (DejaVu Sans),
  как в CI и на Android, — с узким локальным шрифтом переполнение по ширине не видно. Фикстура включает отладочный доступ
  `window.__aiMaster` (флаг localStorage `ai-master:debug`): состояние меняется не правкой хранилища, а действиями —
  `act(page, событие, MASTER/ENGINE)`; перед перезагрузкой — `flushSaves` / `reloadAndContinue`.
  Модульные тесты IndexedDB — через `fake-indexeddb` (`import 'fake-indexeddb/auto'`), у каждого теста своя база.
- `base` в `vite.config.ts` при сборке равен `/dnd_ai_master/` (имя репозитория) — нужно для GitHub Pages.
  При переименовании репозитория обновить `REPO_NAME`.
- `.github/workflows/deploy.yml` прогоняет модульные тесты, собирает сайт, прогоняет e2e-тесты и только при их успехе
  публикует сайт на GitHub Pages (при каждом пуше в `main`). При падении e2e отчёт Playwright сохраняется
  как артефакт `playwright-report`.
  В настройках репозитория: Settings → Pages → Source = **GitHub Actions**.

- Перед коммитом убедиться, что `npm test`, `npm run build` и `npm run test:e2e` проходят без ошибок.
