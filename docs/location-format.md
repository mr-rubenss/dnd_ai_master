# Формат JSON локации

Этот документ описывает, как устроен файл локации. Он нужен и разработчикам, и ИИ-ведущему: когда ИИ будет
генерировать новые локации, он должен выдавать JSON строго в этом формате. Код проверяет каждую
локацию при загрузке (`parseLocation` в `src/game/location.ts`) и отклоняет некорректные данные
со списком ошибок на русском.

Типы TypeScript: `src/types/location.ts`. Пример: `src/data/locations/drunken-griffin.json`.

## Главное: стены тонкие

Как в Roll20 и Foundry, **стена не занимает клетку** — она лежит на границе между клетками.
Клетка бывает только полом (по ней можно ходить) или пустотой (за пределами помещения).
Двери и окна — тоже отрезки на границе, причём только там, где есть стена.

## Система координат

- Карта — прямоугольная сетка из `width × height` клеток. Одна клетка = `cellFeet` футов (по правилам — **5**).
- **Клетка** `(x, y)`: `x` — столбец (0 — левый край), `y` — строка (0 — верхний край).
  Так задаются объекты, НПС, стартовая позиция и комнаты.
- **Узел** `(x, y)` — левый верхний угол клетки `(x, y)`. Узлы идут от `(0, 0)` до `(width, height)`.
  Так задаются стены, двери, окна и проёмы: отрезок `{ "x1", "y1", "x2", "y2" }` от узла до узла,
  строго по горизонтали (`y1 = y2`) или по вертикали (`x1 = x2`).

```
узлы:  (0,0)──(1,0)──(2,0)        отрезок {x1:1, y1:0, x2:1, y2:1} — граница
         │ клетка │ клетка │        между клетками (0,0) и (1,0)
         │ (0,0)  │ (1,0)  │
       (0,1)──(1,1)──(2,1)        отрезок {x1:0, y1:1, x2:2, y2:1} — нижняя граница обеих клеток
```

## Две записи: упрощённая и полная

Пол и стены можно задать двумя способами — и смешивать их.

**Упрощённая (рекомендуется для генерации)** — комнаты прямоугольниками:
- `rooms` — прямоугольники пола. **Стены по периметру каждой комнаты ставятся автоматически.**
  У двух соседних комнат периметры совпадают — между ними сама собой получается стена.
- `walls` — дополнительные стены: перегородки внутри комнаты. Если перегородка совпадает с автоматической стеной,
  она просто задаёт ей материал (например, тонкая деревянная перегородка между залом и кладовой).
- `openings` — проёмы: убирают стены на отрезке. Так из двух прямоугольников делают Г-образный зал
  или прорезают арку без двери. Проём можно сделать только там, где есть стена.
- `doors`, `windows` — двери и окна на стенах.

**Полная** — то, к чему код всегда приводит локацию:
- `floorPlan` — план пола строками символов: `.` — пол, пробел — пустота;
- `walls` — все стены отрезками.

Нужно хотя бы одно из двух: `rooms` или `floorPlan`.

## Структура

```jsonc
{
  "id": "drunken-griffin",            // уникальный id латиницей, kebab-case
  "name": "Таверна «Пьяный грифон»",  // название для игрока
  "description": "Шумная придорожная таверна…", // 1–2 предложения, атмосфера
  "cellFeet": 5,
  "width": 20,                         // ширина в клетках (1–100)
  "height": 14,                        // высота в клетках (1–100)
  "floor": "wood",                     // тип пола
  "wallMaterial": "stone",             // материал стен по умолчанию
  "rooms": [ … ],                      // упрощённая запись
  "walls": [ … ],                      // перегородки / стены
  "openings": [ … ],                   // проёмы
  "doors": [ … ],
  "windows": [ … ],
  "objects": [ … ],                    // предметы обстановки
  "npcs": [ … ],
  "playerStart": { "x": 10, "y": 13 }  // вход: клетка, где появляется игрок
}
```

### Поля верхнего уровня

| Поле           | Тип      | Обяз. | Описание |
|----------------|----------|:-----:|----------|
| `id`           | string   | да    | Уникальный идентификатор локации. |
| `name`         | string   | да    | Название на русском. |
| `description`  | string   | да    | Короткое описание, показывается под названием карты. |
| `cellFeet`     | integer  | да    | Футов в одной клетке. Обычно `5`. |
| `width`        | integer  | да    | Ширина карты в клетках, 1–100. Рекомендуется 10–30. |
| `height`       | integer  | да    | Высота карты в клетках, 1–100. Рекомендуется 8–20. |
| `floor`        | enum     | да    | `wood` (доски), `stone` (камень), `dirt` (земля), `grass` (трава). |
| `wallMaterial` | enum     | да    | Материал стен по умолчанию: `stone` (камень), `wood` (дерево). |
| `rooms`        | array    | *     | Комнаты-прямоугольники. *Нужно `rooms` или `floorPlan`. |
| `floorPlan`    | string[] | *     | План пола: `height` строк по `width` символов `.` или пробел. |
| `walls`        | array    | нет   | Стены-отрезки (перегородки). |
| `openings`     | array    | нет   | Проёмы — убирают стены. |
| `doors`        | array    | нет   | Двери на стенах. |
| `windows`      | array    | нет   | Окна на стенах. |
| `objects`      | array    | да    | Объекты обстановки (может быть пустым `[]`). |
| `npcs`         | array    | да    | НПС (может быть пустым `[]`). |
| `playerStart`  | object   | да    | `{ "x", "y" }` — вход, стартовая клетка игрока, должна быть полом. |

### Комнаты `rooms`

```json
{ "id": "hall", "name": "Общий зал", "x": 0, "y": 5, "w": 20, "h": 9 }
```

| Поле       | Тип     | Обяз. | Описание |
|------------|---------|:-----:|----------|
| `id`       | string  | да    | Уникален среди всех id локации. |
| `name`     | string  | нет   | Название комнаты для ведущего. |
| `x`, `y`   | integer | да    | Левая верхняя клетка. |
| `w`, `h`   | integer | да    | Ширина и высота в клетках, ≥ 1. |

Комнаты не пересекаются и не выходят за пределы карты.

### Стены `walls` и проёмы `openings`

```json
{ "x1": 15, "y1": 0, "x2": 15, "y2": 5, "material": "wood" }
```

| Поле                   | Тип     | Обяз. | Описание |
|------------------------|---------|:-----:|----------|
| `x1`, `y1`, `x2`, `y2` | integer | да    | Концы отрезка — узлы сетки, от `(0, 0)` до `(width, height)`. Только горизонталь или вертикаль. |
| `material`             | enum    | нет   | Только у стен: `stone` или `wood`; по умолчанию — `wallMaterial`. |

У проёма — только координаты. Порядок применения: стены комнат → `walls` → `openings` (проём убирает и те и другие).

### Двери `doors`

```json
{ "id": "storage-door", "name": "Дверь в кладовую", "description": "Низкая дверь за стойкой.",
  "state": "locked", "x1": 15, "y1": 1, "x2": 15, "y2": 2 }
```

| Поле                   | Тип     | Обяз. | Описание |
|------------------------|---------|:-----:|----------|
| `id`                   | string  | да    | Уникален среди всех id локации. |
| `name`                 | string  | да    | Название для подсказки. |
| `description`          | string  | нет   | Что игрок видит. |
| `state`                | enum    | да    | Начальное состояние: `open` (открыта), `closed` (закрыта), `locked` (заперта). |
| `x1`, `y1`, `x2`, `y2` | integer | да    | Отрезок на стене. Обычно длиной 1 клетка; 2 — двустворчатая дверь, ворота. |

Текущее состояние двери хранится в состоянии игры (`location.doors`), начальное берётся отсюда.

### Окна `windows`

```json
{ "id": "window-east", "name": "Окно", "description": "Узкое окно во двор.", "x1": 20, "y1": 8, "x2": 20, "y2": 10 }
```

`id` обязателен, `name` и `description` — нет. Через окно видно, но пройти нельзя.

Правила для дверей и окон:
- стоят **только на стене** — каждый единичный отрезок двери/окна должен совпадать со стеной;
- хотя бы с одной стороны — пол;
- двери и окна не накладываются друг на друга.

### Объекты `objects`

```json
{ "id": "table-1", "type": "table", "name": "Стол у камина",
  "description": "Самое тёплое место в зале.", "x": 3, "y": 7, "w": 2, "h": 2 }
```

| Поле          | Тип     | Обяз. | Описание |
|---------------|---------|:-----:|----------|
| `id`          | string  | да    | Уникален среди всех id локации. |
| `type`        | enum    | да    | Тип объекта, см. таблицу ниже. |
| `name`        | string  | да    | Название для подсказки на карте. |
| `description` | string  | нет   | 1–2 предложения: что игрок видит. Можно оставлять зацепки для сюжета. |
| `x`, `y`      | integer | да    | Левая верхняя клетка объекта. |
| `w`, `h`      | integer | нет   | Ширина и высота в клетках, по умолчанию `1`. |

| `type`      | Что это | Типичный размер | Где ставить |
|-------------|---------|-----------------|-------------|
| `table`     | Стол | 2×2, 2×1 | На пол. |
| `chair`     | Стул | 1×1 | На пол, рядом со столом. |
| `bar`       | Барная стойка | 6–10×1 или 1×6–10 | На пол. |
| `fireplace` | Камин | 1×2–3 или 2–3×1 | На пол вплотную к стене. |
| `barrel`    | Бочка | 1×1 | На пол. |
| `fire`      | Огонь на полу | 1×1 и больше | На пол (пожар, костёр, разлитое горящее масло). |
| `debris`    | Обломки, завал | 1×1 и больше | На пол (упавшая люстра, обрушенные балки). |
| `item`      | Прочий предмет | 1×1 | На пол (ящик, сундук, мешок). |

Во время игры ведущий меняет обстановку инструментами `add_object` / `update_object` / `remove_object`
(`src/game/masterTools.ts`); движок проверяет координаты, пол, стены и что клетки свободны.

Двери — не объекты: они задаются в `doors`.

Правила размещения:
- все клетки объекта — пол, объект не выходит за пределы карты;
- объект не стоит поперёк стены;
- два объекта не занимают одну клетку (НПС при этом может стоять на клетке объекта, например на стуле).

### НПС `npcs`

```json
{ "id": "gunnar", "name": "Гуннар", "description": "Трактирщик, рыжебородый, знает все слухи.",
  "attitude": "friendly", "x": 7, "y": 1 }
```

| Поле          | Тип     | Обяз. | Описание |
|---------------|---------|:-----:|----------|
| `id`          | string  | да    | Уникален среди всех id локации. |
| `name`        | string  | да    | Имя — показывается подписью под фишкой. Лучше короткое (1–2 слова). |
| `description` | string  | нет   | Внешность и поведение — то, что игрок видит с первого взгляда. |
| `attitude`    | enum    | нет   | Отношение к игроку: `friendly`, `neutral` (по умолчанию), `hostile`. Определяет цвет фишки. |
| `x`, `y`      | integer | да    | Клетка, где стоит НПС. Должна быть полом (можно на клетке стула). |

## Движение и видимость

Правила — в `src/engine/movement.ts`:
- `canStep` / `stepBlocker` — можно ли шагнуть из клетки в соседнюю (по стороне или по диагонали).
  Нельзя через стену, окно, закрытую или запертую дверь. По диагонали нельзя, если у общего угла клеток
  есть хоть одна стена (нельзя «протиснуться» между углами стен или обогнуть конец перегородки).
- `hasLineOfSight` — заготовка линии видимости между центрами клеток: её перекрывают стены и закрытые двери,
  окна и открытые двери — нет.

## Чек-лист для генерации

1. Есть `rooms` (проще) или `floorPlan`; размеры комнат и отрезков — в пределах карты.
2. Все `id` уникальны в пределах локации.
3. Отрезки идут по линиям сетки строго по горизонтали или вертикали, концы — целые узлы.
4. Двери, окна и проёмы — только на стенах (на периметре комнаты или на перегородке).
5. **Все клетки пола достижимы от входа** `playerStart` — через проёмы или двери (в любом состоянии,
   даже запертые). Окна комнаты не соединяют. Отрезанная комната — ошибка.
6. Объекты, НПС и `playerStart` стоят на полу; объекты не пересекаются и не стоят поперёк стен.
7. Все тексты для игрока — на русском.
8. Описания не раскрывают скрытое: тайны и ловушки описывают так, как их видит невнимательный
   наблюдатель (детали узнаются через проверки, которые бросает код).

## Полный пример

См. `src/data/locations/drunken-griffin.json` — таверна 20×14 в упрощённой записи: зона у стойки и общий зал
(две комнаты, соединённые проёмом), кладовая за тонкой деревянной перегородкой с запертой дверью,
двустворчатая входная дверь, три окна, стойка, пять столов, камин, трактирщик и трое посетителей.
