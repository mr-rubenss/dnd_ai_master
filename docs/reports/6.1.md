# Отчёт: задача 6.1 — генерация локаций ведущим (`create_location`)

## Что сделано

- Новый инструмент ведущего **`create_location`**: модель присылает JSON карты в формате `docs/location-format.md`
  (название, описание, размер, комнаты, двери, объекты, НПС, выходы, вход). Краткое описание формата — прямо
  в описании инструмента, чтобы модели не нужно было видеть документ.
- **Проверка в два шага** (`src/game/locationCreate.ts`):
  1. схема **zod** (`CREATED_LOCATION_SCHEMA`, сборка `zod/mini`): типы полей, допустимые значения, пределы (карта до
     60×60, до 120 объектов, 20 НПС, 1–10 выходов, длина текстов); ошибки по-русски с путём поля:
     «objects[0].type: одно из table, chair, …», «exits: нужно хотя бы 1 (у локации должен быть хотя бы один выход)»;
  2. существующий `parseLocation` (стены и двери на стенах, всё на полу, **объекты не за пределами карты и не друг на
     друге**, весь пол достижим от входа) и правила созданной локации: **хотя бы один выход**, НПС по одному в клетке,
     выходы не в одной клетке, id не занят.
  Ошибки (до 12 за раз) возвращаются модели списком: «Локация не создана, исправь и вызови снова: …» — она исправляет
  и вызывает снова. История при отказе не меняется.
- **Выходы** — новая часть формата любой локации: `exits` (`door`/`road`/`stairs`/`edge`, клетка пола у выхода,
  у двери — id двери вплотную, у края карты — клетка на краю, `to`/`toExit` — куда ведёт). Описано в
  `docs/location-format.md` (раздел «Выходы», чек-лист, раздел о созданных локациях).
- **Хранение**: действие `locationCreated` (только ведущий) кладёт проверенную локацию в мир истории
  (`world.locations`). Проверка действия перепроверяет саму локацию тем же `parseLocation` (полную запись можно
  перевести обратно — `locationInputOf`), так что испорченная карта не пройдёт, откуда бы ни пришло действие.
  При воспроизведении журнала и после перезагрузки — та же карта. Повторное создание с тем же id — отказ
  «уже есть в мире этой истории — не создавай заново».
- **Ведущему** в состоянии игры: «Выходы в другие локации» у текущей локации (куда ведёт, создана ли) и раздел
  «Локации мира» — какие карты уже есть (не создавать их заново). Правило «Новые места» в `dm-prompt.md`,
  сценарий 43 в `docs/dm-test-scenarios.md`.
- Тесты: `src/game/locationCreate.test.ts` (10: схема, наложения, выходы, достижимость, инструмент, повтор id,
  JSON строкой, кто может создать, перепроверка действия, перевод формата туда-обратно), отказы в
  `masterTools.test.ts`, e2e `e2e/create-location.spec.ts` (ошибочный JSON → модель получает ошибки → исправленный
  сохраняется → перезагрузка → локация на месте и видна ведущему в «Локациях мира»).

Проверки: `npm test` — 824 passed, `npm run lint` — чисто, `npm run build` — ок, e2e — 248 passed / 24 skipped.

## Оговорки и что выбрал сам

- `zod/mini` вместо полного `zod`: тот же zod, но маленькая сборка — CLAUDE.md бережёт вес браузерной сборки
  (темы проверяются zod только при сборке). Основной файл сайта сейчас ~1,21 МБ (357 КБ gzip).
- Пределы созданной карты (60×60, 120 объектов, 20 НПС, 10 выходов) выбрал сам — чтобы состояние игры в запросе
  к модели не разрасталось. У шаблонов из `src/data/locations/` пределы прежние (до 100×100).
- Правила «НПС по одному в клетке» и «выходы не в одной клетке» — только для созданных ведущим локаций, чтобы
  не трогать старые данные.
- Выходы для старых шаблонов необязательны (у таверны их пока нет) — выход из таверны добавлю в 6.6, где нужны переходы.
- Дверь-выход (`kind: door`) обязана ссылаться на дверь локации; дорога и лестница — просто клетка пола.
- `to` у выхода может указывать на ещё не созданную локацию (её создадут при переходе, 6.6).
- Скрытые объекты/НПС, эффекты и скрытые зоны в созданной локации разрешены (как в формате).
- Инструмент не переносит героя на новую карту и не меняет текущую локацию — это 6.6.
- Тест-перечень инструментов в `masterTools.test.ts` дополнен новым именем — это обычное обновление списка, не ослабление.
