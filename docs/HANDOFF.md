## Решения и договорённости (нет в коде явно или разбросаны)

- Боевой системы нет (этап 8). До неё: гибель НПС словами запрещена (`remove_npc` died → отказ), урон героя только
  `change_hp` с `dice`. `set_combat` — заготовка: только раунды и скорость передвижения, без атак/инициативы. Если
  владелец не хочет заготовку — её легко убрать (`combat` в StoryState, `combatBudget`, `limitBySpeed`).
- Награды: `REWARD_TIERS` — ур. 1–4: 100 зм / uncommon; 5–10: 1000 / rare; 11–16: 10000 / very-rare; 17–20: 100000 /
  legendary. Источник обязателен (`source` + `from`).
- Правило SRD «16 часов до следующего долгого отдыха» не применяется (функция `longRestWait` готова, этап 8.5).
- Кость хитов на коротком отдыхе даёт минимум 1 хит (наше решение, SRD молчит).
- Диагональ = 5 фт. (правила 2024). Дальность тёмного зрения — по Чебышёву (клетки × 5 фт.), радиус света —
  евклидов (как рисуется круг). Сознательная непоследовательность.
- Области воздействия (`src/engine/areas.ts`): клетка задета, если фигура покрывает ≥ половины клетки (16 образцов)
  и до покрытых точек есть неперекрытая прямая от точки начала. Фигуры по умолчанию геометрические (как в SRD) — по
  диагонали они короче, чем клеток на линейке (линия 30 фт. по диагонали — 4 клетки, линейка «диагональ — 5 фт.»
  считает 4 диагональные клетки как 20 фт.). Есть готовая метрика `grid` (`AreaGrid.metric`): фигуры по правилу сетки,
  сфера — квадрат. Какую брать в бою/заклинаниях — спросить владельца (сейчас везде `euclidean`).
- Для областей окно — полное укрытие (как стена; `segmentBlocked(..., 'solid')`), для взгляда — нет.
- «От себя» (герой, НПС, объект): конус и линия начинаются у края клетки в сторону направления, куб — от середины
  грани или угла (8 направлений), сфера и цилиндр — из центра, излучение — вокруг пространства. На пустом месте
  начало прилипает к сетке с шагом полклетки; размер жеста — шагом в клетку, не меньше 5 фт.
- Область ведущего (`areaShown`) видна 30 с (`AREA_SHOW_MS`) или до «Скрыть»; только новая (как ping). Игроку в
  «Задеты» — только видимые (скрытые и в тумане — нет), ведущему — все, скрытые с пометкой.
- Панель «Линейка | Области» — строкой над картой, а не поверх: иначе на телефоне закрывает фишки, по которым жмут тесты.
- Цвета тем без согласия владельца не менять; новые элементы карты (эффекты, туман) — только существующими токенами,
  новых токенов не заводил, чтобы не трогать JSON тем дизайнера.
- Реплики меню карты: имена в кавычках без склонения («Подхожу к «Тобиас».»), без слова «НПС».
- Ведущий двигает героя только `move_hero` (target, не координаты; координаты — только по сюжету с reason).
- Исследованное (туман) пишет `GameScreen` действием `areaExplored` автором SYSTEM — и при выключенном тумане.
- Скрытые НПС/объекты занимают клетку («что-то мешает»), светом себя не выдают.
- Пауза авто-реакции на значимое перемещение — 20 с (`src/data/map-reactions.json`).
- Подменённые ответы в e2e/модульных тестах: если в реплике игрока глагол перемещения («подхожу», «сажусь», «иду к»),
  сверка карты попросит `move_hero` — лишний запрос. В старых тестах реплики заменены нейтральными; новые тесты писать
  так же или подкладывать вызов `move_hero`.

- Метки (5.7): общий список `world.marks` (локация + клетка), одна на клетку, до 50 на карту, текст до 40, только
  игрок своего героя. Ведущему — ближайшие 10 с тем, что рядом (и скрытое). Долгое нажатие — `LONG_PRESS_MS` 550.
- `create_location` (6.1): `zod/mini` (не полный zod — вес сборки); пределы `CREATED_LOCATION_LIMITS` (60×60, 120
  объектов, 20 НПС, 1–10 выходов). `locationCreated` перепроверяется через `locationInputOf` → `parseLocation`.
- Переходы (6.6): у выхода-двери значка нет (меню двери), у остальных — значок в слое фишек. Путь отряда —
  `world.trail` (толкование «путь вверху» — вопрос владельцу). Старые истории — таверна без выхода (данные не правил).
- У событий нельзя заводить поле `at` на верхнем уровне (как и `id`): `makeAction` затирает его временем действия.

## Известные проблемы / оговорки (не исправлены)

- «Подойти» из меню, когда герой уже рядом: реплика уходит без `move`, сверка карты просит `move_hero` → лишний
  запрос («уже рядом»). Владелец предупреждён, не исправлено.
- Видят ли НПС героя — только по линии видимости, без света и тёмного зрения НПС. Мебель и существа взгляд не
  перекрывают. Дым скрывает свои клетки, но не перекрывает взгляд сквозь себя.
- Мобильный Chrome «притягивает» нажатие к ближайшему кликабельному элементу: тап по клетке рядом с мебелью/НПС может
  открыть меню. Поэтому часть e2e — только мышью.
- Туман раскрывается по итоговой позиции героя сразу, до конца анимации шага.
- Старые истории без `world.explored` — исследованное начинается с текущего вида (не беда).
- Сводка измерения на телефоне закрывает правый верх карты (кладовую) — есть «×». Существа в областях считаются
  размером 1 клетка (у НПС и героев нет размера). Высота цилиндра на плоской карте только в подписи.
- Линейка меряет от клетки до клетки (центры), без учёта стен — как правило «Ranges», а не путь.
- Не сделано по SRD — `docs/srd/reconciliation.md`, раздел «Не сделано» (приёмы в бою, временные хиты, усиление
  заговоров и ячеек и т. п.).

## Тесты, сборка, e2e — как и подводные камни

- e2e на телефоне: `click()` по кнопке — это мышь, курсор остаётся и может открыть подсказку при наведении на предмет;
  для телефона — `tap()`. Долгое нажатие пальцем — через CDP `Input.dispatchTouchEvent` (см. `e2e/marks.spec.ts`).
- Тест порядка слоёв карты (`e2e/map-view.spec.ts`) сверяет список `.map-layer` целиком — новые элементы класть
  в существующие слои (или слой только при наличии данных, как метки).
- `npm test` (Vitest, ~5 с), `npm run lint` (oxlint), `npm run build` (tsc + vite), `npm run test:e2e` (Playwright,
  ~3.5 мин, нужен свежий `npm run build` — e2e идут по `dist/`). Перед коммитом — все четыре.
- Запускать e2e с `--trace off` (быстрее): `npx playwright test --trace off`; один файл — `npx playwright test e2e/x.spec.ts --trace off`.
  Полный прогон дольше 2 мин — в Bash ставить timeout 600000 (или фон).
- Chromium предустановлен, `playwright install` не запускать.
- e2e: `test`/`expect` только из `e2e/fixtures.ts`; состояние менять `act(page, событие, MASTER/ENGINE)`; перед
  перезагрузкой `flushSaves`/`reloadAndContinue`. API ведущего подменять `page.route` + `withEndTurn` (из helpers).
- Быстрые анимации ловить `expect.poll(..., { intervals: [50] })` — обычный expect опрашивает редко (уход НПС ~1 с).
- `makeAction` кладёт поле `id` действия поверх события — у событий не должно быть своего поля `id` на верхнем уровне
  (поэтому `entityRevealed.entityId`).
- Тест `memory.test.ts` «окно не превышается» чувствителен к размеру описаний инструментов: новые инструменты могут
  потребовать увеличить запас в тесте.
- `noRawColors` и `theme.test.ts`: никаких сырых цветов вне `src/theme/`; CSS-переменные карты — kebab-case
  (`--map-fire-glow`, а не `--map-fireGlow`).
- Тест `appearance.test.ts` сверяет `root.dataset` целиком — новый атрибут оформления = правка теста.
